[Celld：自托管分布式 Durable Objects](https://github.com/denoland/celld) ⭐️ 9.0/10

Deno 在 GitHub 发布 Celld，一个开源、可自托管、分布式的 Durable Objects 运行时，采用 S3 兼容对象存储做复制。项目主打“每个对象就是自己的 SQLite 数据库，按名称寻址，并复制到你拥有的 S3 兼容存储桶”，让开发者可以把类似 Cloudflare Durable Objects 的对象寻址与存储抽象运行在自己控制的基础设施上。目前项目处于早期阶段，生产环境验证有限；仓库还关闭了 Pull Request，要求通过 git format-patch 提交补丁。Hacker News 上相关讨论获得 216 分、35 条评论，具体版本和完整能力仍需以仓库 README 为准。

hackernews · calvinfo · 8月5日 16:50 · [社区讨论](https://news.ycombinator.com/item?id=49185430)

**「为何重要」** Celld 提供了一个打破单一厂商绑定的选项：此前 Durable Objects 主要依赖 Cloudflare 生态，现在团队可以用同一抽象自行部署，并借助 S3 兼容存储降低运行门槛。对已经使用 Workers/Durable Objects 的团队，它可能成为迁移、灾备或混合部署的候选方案；对自托管倾向的开发者，这则是一种新的有状态计算原语。不过，由于项目尚在早期，API 稳定性、性能和生产工具链都还没有得到广泛验证。

**「内容角度」** \1. 对照 Celld 与 Cloudflare 开源的 workerd：社区里已经有人直接问两者差别，可以梳理它们各自解决什么问题，以及部署方式、存储接口和供应商绑定上的取舍。2. 实战迁移一个简单有状态应用：参考社区成员用 Cloudflare Durable Objects 搭建芒果品鉴活动签到应用的经验，尝试把类似小应用搬到 Celld 自托管，验证 S3 复制和“按名称寻址”是否开箱即用。3. 关注开源维护模式：Celld 关闭 Pull Request、要求 git format-patch，侧面反映编码代理时代维护者应对“低上下文大改动”的审查负担，可以探讨这种协作方式对社区参与的影响。

**「社区讨论」** Hacker News 评论中有人为“终于可以把 Durable Objects 跑在单一厂商之外”叫好，并分享了自己用 Cloudflare 实现活动小程序的经验；也有人提出最直接的问题：这类能力到底能用来做什么，以及它与 Cloudflare workerd 的差别。维护者还说明了关闭 PR、要求通过 git format-patch 提交的原因，担心编码代理制造的“低上下文、大改动”补丁会消耗过多维护时间。
